# 案件要件分析框架

基于《上海法院类案办案要件指南》的六段式审判方法论，为法律从业者提供案件办理的全流程指引。适配仲裁场景，将法院审判框架转化为仲裁审查框架。

引用与防幻觉规则见知识库 `CITATION.md`；涉及法条/规则先检索共享知识库。

## 适用场景

1. **案件类型识别**：用户描述案情 → 匹配最可能的案由和置信度
2. **审查清单生成**：按六段式框架输出可检核的审查要点清单
3. **双向视角分析**：同时输出申请人/被申请人视角的策略建议
4. **法律咨询问答**：回答法律依据、证据要求、办理流程等问题
5. **补强建议**：识别材料缺失要素，匹配优先级排序的补强建议

## 六段式框架结构

上海法院六段式审判框架（仲裁化适配后）：

1. **总体情况概述** — 案件特点、审查原则
2. **立案审查** — 主管、管辖、当事人主体资格
3. **申请人请求的审查** — 各项仲裁请求的审查要点
4. **被申请人抗辩的审查** — 各类抗辩理由的审查要点
5. **要件事实审查和裁判规则** — 核心法律关系、证据规则
6. **知识图谱** — 核心要点可视化总结

每个要件的子结构：
- 审查要点（核心要素）
- 注意事项（易错点）
- 规范指引（法律法规、司法解释）
- 典型案例（类案参考）

## 工具链

| 工具 | 用途 | 使用时机 |
|------|------|---------|
| `identify_case_type` | 识别案件类型 | 用户描述案情后 |
| `generate_review_checklist` | 生成要件清单 | 确定案件类型后 |
| `dual_perspective_analysis` | 双向视角分析 | 需要策略建议时 |
| `legal_qa_consultation` | 法律问答 | 用户提问时 |
| `search_knowledge` | 法条检索 | 需要法条依据时 |

## 处理流程

### 阶段1：案件识别

用户描述案情后，调用 `identify_case_type` 工具：

```
用户：朋友向我借款10万元，现在借款不还
→ 调用 identify_case_type(query="朋友向我借款10万元，现在借款不还")
→ 返回：民间借贷（置信度 33.3%，匹配关键词：借款、借贷）
```

### 阶段2：框架分析

确定案件类型后，调用 `generate_review_checklist` 生成审查清单：

```
→ 调用 generate_review_checklist(case_type="民间借贷", perspective="neutral")
→ 返回：六段式审查要点清单（立案审查、申请请求、被申请人抗辩、要件事实）
```

支持三种视角：
- `applicant`：申请人视角（重点：立案审查 + 申请请求 + 要件事实）
- `respondent`：被申请人视角（重点：抗辩审查 + 要件事实）
- `neutral`：中立视角（全量框架）

### 阶段3：策略建议

调用 `dual_perspective_analysis` 进行双向视角分析：

```
→ 调用 dual_perspective_analysis(case_type="民间借贷", materials_summary="...")
→ 返回：
  - 申请人视角：优势点 / 劣势点 / 证据清单 / 胜诉概率
  - 被申请人视角：薄弱点 / 抗辩策略 / 反证清单 / 预期效果
  - 补强建议（优先级排序）
```

### 阶段4：法律咨询

调用 `legal_qa_consultation` 回答具体法律问题：

```
→ 调用 legal_qa_consultation(question="民间借贷的利率上限是多少？")
→ 返回：基于问题类型分类的结构化回答
```

支持5种问题类型：
1. 案件识别："这是什么纠纷？"
2. 法律依据："有什么法律依据？"
3. 证据清单："需要什么证据？"
4. 流程指导："怎么办理？"
5. 一般咨询：其他法律问题

## 输出规范

1. 所有分析结果标注数据来源
2. 法条引用前先用 `search_knowledge` 检索
3. 证据清单标注必要性等级（必需/重要/辅助）
4. 补强建议标注优先级（1-5）和预计时间
5. 双向视角分析中，优势/劣势要具体到审查要点编号

## 禁止事项

- 不推测数据库中不存在的案件类型
- 不编造审查要点或法条依据
- 不在未检索的情况下引用法条
- 不将分析结果定性为最终法律意见
- 仲裁化适配不得改变法律本意
