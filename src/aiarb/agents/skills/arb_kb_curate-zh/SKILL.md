# 仲裁知识库策展

把内容整理进共享知识库，让后续检索真正能用。

**先读规范**：`knowledge_base/SCHEMA.md`（文档头）、`SOURCES.md`（版权边界）、`CITATION.md`（引用规则）。

## 策展流程

### 第一步：判定能否入库

按 `SOURCES.md` 第 1 条判定：

| 内容 | 处置 |
|---|---|
| 法律法规官方文本 | ✅ 可全文入库 |
| 仲裁机构公开规则 | ✅ 可全文入库，注明机构/版本/来源 URL |
| 公开案例 | ⚠️ 只入结构化整理（案由/焦点/要旨），**不整篇复制原文** |
| 公众号/媒体分析文章 | ❌ 不入库，仅作线索，回溯官方源核对 |
| 实务书籍、他人模板 | ❌ 不入库 |
| 用户自有案件材料 | ❌ 不进共享库，留私有工作区（脱敏后可入） |

**存疑即不入库**，记为待办并提示用户判断。

### 第二步：脱敏

入库前移除：当事人姓名/名称、身份证号、统一社会信用代码、银行账号、联系方式、仲裁员姓名、具体金额（保留数量级或计算逻辑）。

替换规则：申请人 / 被申请人 / A 公司 / B 公司。

案例文件必须设 `redacted: true`；`redacted: false` 禁止放入共享库。

### 第三步：补全文档头

按 `SCHEMA.md` 补齐必填字段。最关键三项：

- `source` —— 来源 URL 或路径
- `source_type` —— official / public-web / user-upload / curated
- `retrieved` —— 采集日期

**缺来源的文件不予入库**。

`confidence` 取值：与原文逐字核对过为 `verified`；未经核对为 `draft`（引用时会提示复核）。

### 第四步：归档到正确目录

| 内容 | 目录 | 命名 |
|---|---|---|
| 法律法规 | `laws/` | `<名称>-<年份>.md` |
| 机构规则 | `rules/` | `<机构缩写>-仲裁规则-<年份>.md` |
| 案例整理 | `cases/` | `<机构>-<案号或主题>-<年份>.md` |
| 文书模板 | `templates/` | `<文书类型>.md` |

主题性案例可放 `cases/<主题>/` 子目录。

### 第五步：登记台账

在 `SOURCES.md` 的入库登记台账追加一行：文件、类别、来源、类型、采集日、版权状态、状态。

**无登记即视为未授权**。

### 第六步：验证

用 `search_knowledge` 或 `grep_search` 检索刚入库文件的关键词，确认能被命中。检索不到要检查文件名与文档头。

## 正文整理要求

1. **条文/条款逐字录入**，保留原编号体系，不改写、不"优化"。
2. **案例只做结构化归纳**，用自己的话写要旨，不抄原文段落。
3. **长文件标注定位信息**（页码、条款号），便于引用时精确定位。
4. **发现冲突时标注**，不自行取舍：`> 注：与 X 版本存在冲突，待核对`。

## 禁止事项

- 不凭记忆生成法条、规则条款、案号、裁判要旨
- 不整篇复制受版权保护的内容
- 不把未脱敏材料写入共享库
- 不跳过台账登记

## 建议的采集顺序

1. 先补 `rules/`（机构公开规则，无版权障碍，见效最快）
2. 再补 `laws/`（官方文本）
3. 然后 `templates/`（结构模板）
4. 最后 `cases/`（从已有核阅成果脱敏反推，价值最高但最费工）
