## 一、三种模式概述

| 模式 | 存储 | 触发方式 | 适用场景 |
|------|------|---------|---------|
| **详版** (full) | 默认，无 localStorage key | 默认状态 | 开发者/管理员日常使用 |
| **简版** (simple) | `aiarb_sidebar_mode = "simple"` | Sidebar 伸缩按钮 | 终端用户、小屏设备 |
| **设计版** (design) | `aiarb_sidebar_mode = "design"` | 设计面板按钮 | AI 应用设计者 / 插件开发者 |

## 五、架构分析

### 5.1 当前菜单设计的问题

1. **"智能体工作区"与"仲裁业务"概念重叠**：对于仲裁用户，"工作区文件"、Agent 配置等其实是辅助性的，不应与核心仲裁功能平级
2. **设置项过于平铺**：两个 settings group 共 17 个设置项，简版下只暴露 2 个，其余对于 C 端用户是噪音
3. **简版设计是妥协方案**：simple 模式用白名单硬砍菜单，而不是从场景出发设计导航
4. **设计版混杂生产功能**：design.* 专属页（Skills/Agent/Ops）与生产功能（Chat/Models/Channels）混在同一导航
5. **仲裁业务区始终全量可见**：即使某个功能（如 Wiki/案件卷宗）对当前用户不适用，也占据导航位置

### 5.2 从 C 端用户和仲裁个人用户的视角

**C 端用户（通用场景）**：
- 只需：Chat 对话、知识库管理、设置（模型、Agent）
- 不需要：仲裁专用功能（模拟仲裁、案件卷宗、文档智能脱敏）、运维功能
- 当前被仲裁业务区占据过多导航空间

**仲裁个人用户（垂直场景）**：
- 核心工作流：上传文档 → 脱敏 → 入知识库 → Agent 辅助分析
- 高频：文档智能、本地资料、Chat 对话
- 中频：Wiki、案件卷宗、模型设置
- 低频：渠道、会话、调试、备份等运维功能
- 当前缺乏清晰的"工作流引导"导航

## 六、菜单改造建议

### 方案 A：场景化主菜单（推荐）

```
📱 C端 / 仲裁 全局共享顶部图标
├── 💬 对话 (/chat)          ← 默认首页
├── 📚 知识库 (/knowledge)    ← 合并 Wiki 作为子Tab
├── 🛡️ 文档智能 (/desensitize) ← 仲裁用户高频
├── ⚖️ 模拟仲裁 (/moot)       ← 仲裁专属
├── 📋 案件卷宗 (/cases)      ← 仲裁专属
└── ⚙️ 设置 (/models)        ← 收敛所有配置
    ├── 模型管理
    ├── Agent 管理
    ├── 渠道与会话
    ├── 系统（环境变量/安全/备份/插件/定时任务等）
    └── 高级（调试/统计/语音转写等）
```

**优点**：
- 仲裁用户核心流程（文档→脱敏→知识库）首屏可触达
- C 端用户看不到仲裁专属项（可通过配置开关）
- 所有"设置"收敛到一个入口，减少认知负担

### 方案 B：双模式切换

```
普通模式（C端）：                    仲裁模式（仲裁用户）：
├── 💬 对话                         ├── 💬 对话
├── 📚 知识库                        ├── ⚖️ 仲裁工作台（新聚合页）
├── 🧠 技能                          │    ├── 文档智能
├── ⚙️ 设置                          │    ├── 模拟仲裁
│   ├── 模型                         │    ├── 案件卷宗
│   ├── Agent                        │    └── Wiki
│   └── ...                          ├── 📚 知识库
└── (仲裁功能不可见)                  ├── 🛡️ 文档智能
                                     └── ⚙️ 设置
```

**优点**：两类用户互不干扰
**缺点**：增加维护成本，"仲裁工作台"聚合页需要新开发

### 方案 C：渐进式导航（当下最易实施）

保持现有结构，做最小改动：

1. **仲裁业务区增加折叠/排序能力**：用户可拖拽排序、隐藏不常用项
2. **设置区收敛为"设置总览"页**：类似系统偏好设置，二级分类展示
3. **增加"工作流引导"卡片**：在首页提示"下一步：去文档智能处理文档 →"
4. **简版白名单从硬编码改为可配置**：允许用户在简版下自行勾选常用功能

| 阶段 | 内容 | 工作量 |
|------|------|--------|
| **即刻** | 将"设置"的下两个 group 合并为一个"系统设置"组，去除运维/调试的概念隔离 | 低 |
