> 版本：v2.0 | 更新日期：2026-07-12

## 1. 产品概述

### 1.1 产品定位

**文档工坊**是 AIArb 面向法律从业者（特别是仲裁领域）的文档智能处理中心，提供从文档解析、脱敏到知识入库的全链路能力。核心理念：

- **安全透明**：每个处理环节明确标识数据流向（本地/云端），用户始终掌控数据安全
- **渐进增强**：基础能力开箱即用（零配置），高级能力按需启用
- **材料版本管理**：区分原版与脱敏版，AI使用时按需选择

### 1.2 命名体系

| 旧名称 | 新名称 | 说明 |
|--------|--------|------|
| 文档智能 / Desensitize | **文档工坊 / DocForge** | 统一品牌名，涵盖解析+脱敏+入库 |
| 知识库 / Knowledge | **材料库** | 原始文件存储，支持原版/脱敏版 |
| Wiki / 知识编译 | **知识卡片** | AI整理的结构化知识，供AI检索使用 |
| 案件档案 / Cases | **案件卷宗** | 按案件归档管理材料 |

### 1.3 功能模块关系

```
材料库（原始文件） ──→ 文档工坊（解析+脱敏） ──→ 知识卡片（结构化知识）
       ↑                      │                        ↑
       │                      ↓                        │
       └──────── 案件卷宗（按案件归档）←───────────────┘
```

- **材料库**：存放原始文件，是所有文档的源头
- **文档工坊**：对材料进行解析（提取文字）和脱敏（替换敏感信息），输出脱敏版材料
- **知识卡片**：AI将材料提炼为结构化知识卡片，供智能体检索使用
- **案件卷宗**：按案件维度组织材料，一个案件可包含多份材料（原版+脱敏版）

### 2.1 整体布局

### 2.2 安全配置面板（核心新增）

在"文档脱敏"Tab 顶部，新增**安全配置面板**，让用户在每个环节明确数据安全级别：

```
┌──────────────────────────────────────────────────────┐
│ 🛡️ 安全配置    🟢 全程本地处理，数据零外传              │
│ ┌─────────────────────┐ ┌─────────────────────┐      │
│ │ 📄 解析引擎          │ │ 🙈 脱敏模式          │      │
│ │ [🟢 本地优先    ▾]   │ │ [🟡 规则+AI辅助  ▾] │      │
│ │ PyMuPDF→Tesseract   │ │ 规则先处理，AI补充   │      │
│ │ 自动降级，数据不出机器│ │ 识别遗漏            │      │
│ └─────────────────────┘ └─────────────────────┘      │
└──────────────────────────────────────────────────────┘
```

#### 2.2.1 解析引擎选项

| 选项 | 安全级别 | 说明 |
|------|---------|------|
| 🟢 本地优先 | 安全 | PyMuPDF → Tesseract 自动降级，数据不出机器 |
| 🟡 云端OCR | 注意 | MinerU API，精度更高，文档上传至云端 |
| 🟢 仅本地 | 最安全 | 禁用一切云端请求，适合保密文件 |

#### 2.2.2 脱敏模式选项

| 选项 | 安全级别 | 说明 |
|------|---------|------|
| 🟢 规则脱敏 | 安全 | 本地正则引擎，零网络请求 |
| 🟡 规则+AI辅助 | 注意 | 规则先处理，AI补充识别遗漏（需云端模型） |
| 🟢 规则+本地AI | 安全 | 规则先处理，本地AI补充识别（需本地模型） |

#### 2.2.3 安全概览标签

根据配置组合，顶部显示安全概览：

| 组合 | 概览标签 |
|------|---------|
| 解析=本地优先/仅本地 + 脱敏=规则/规则+本地AI | 🟢 全程本地处理，数据零外传 |
| 解析=本地优先/仅本地 + 脱敏=规则+AI辅助 | 🟡 部分环节使用云端，请注意隐私政策 |
| 解析=云端OCR + 脱敏=规则+AI辅助 | 🔴 原始敏感数据将经云端，请确认授权 |

### 2.3 文档解析工作区安全标识

在"文档解析"Tab 顶部，显示简洁的安全标签栏：

```
🟢 本地优先  PyMuPDF → Tesseract 自动降级，数据不出机器
```

### 2.4 文件选择

- 统一使用"选择文件"/"选择文件夹"概念，**不使用"上传"术语**
- 支持本地文件多选（PDF/Word/Excel/PPT/图片等）
- 支持文件夹批量扫描
- 所有文件均在本地处理，不经过服务器上传

### 2.5 代号策略（脱敏后处理）

| 策略 | 说明 |
|------|------|
| 🟢 全局一致 | 同一主体跨材料统一代号（如"申请人A"在所有材料中一致） |
| 文档独立 | 每份材料独立编号 |

代号一致性需要处理以下场景：
- **称呼不一致**：仲裁申请书中"A公司"，笔录中"申请人"→统一代号
- **相对性称呼**：有反请求时，被申请人自称为"反请求申请人"→上下文感知
- **代号映射表**：记录敏感信息→代号的映射规则，支持跨材料引用

## 3. 材料版本管理

### 3.1 原版 vs 脱敏版

| 维度 | 原版 | 脱敏版 |
|------|------|--------|
| 存储位置 | 材料库 | 材料库（标记为脱敏版） |
| 内容 | 原始敏感信息 | 敏感信息替换为代号 |
| AI使用 | 需用户明确授权 | 默认可用 |
| 安全级别 | 🔴 高风险 | 🟢 安全 |

### 3.2 AI使用时的材料选择

当用户在聊天/智能体中使用AI功能时：
- 默认使用脱敏版材料（安全优先）
- 用户可手动切换为原版材料（需确认安全提示）
- 案件卷宗中可批量设置材料版本偏好

### 3.3 知识卡片与材料的关系

- 知识卡片基于脱敏版材料生成（默认）
- 知识卡片可关联到原版材料（供溯源）
- 知识卡片供AI检索使用时，不包含原始敏感信息

## 4. 解析引擎分层架构

### 4.1 第一层：始终预置（~50 MB）

| 组件 | 大小 | 能力 |
|------|------|------|
| PyMuPDF | 19 MB | 数字版PDF文本提取，零依赖 |
| MarkItDown[all] | ~30 MB | Office文档+有文本层PDF提取 |

**能力**：数字版PDF和Office文档的文字提取，不需要OCR即可工作。

### 4.2 第二层：按平台预置 OCR（~76 MB）

| 组件 | 大小 | 能力 |
|------|------|------|
| Tesseract引擎+chi_sim | 62 MB | 扫描版PDF和图片OCR |
| Poppler便携版 | 15 MB | PDF转图片（供OCR使用） |
| pytesseract+pdf2image | 0.03 MB | Python绑定 |

**能力**：扫描版PDF和图片的OCR。Windows随安装包分发便携版；macOS/Linux引导安装。

### 4.3 第三层：可选高级 OCR

| 方案 | 安装 | 说明 |
|------|------|------|
| MinerU云端API | 零安装 | 需联网，精度最高 |
| MinerU本地部署 | ~500 MB | 一键部署，完全本地 |

**能力**：复杂版面、手写体、低质量扫描件的高精度OCR。

### 4.4 自动降级策略

```
用户选择文档
    │
    ├─ 有文本层？──是──→ PyMuPDF提取 → 输出
    │
    ├─ 无文本层（扫描件/图片）──→ Tesseract OCR → 输出
    │
    └─ Tesseract精度不足？──→ 提示配置MinerU → 用户选择是否启用
```

## 5. 脱敏流程设计

### 5.1 处理流程

```
原始文档
    │
    ├─ Step 1: 解析（提取文本）
    │   └─ 安全级别由"解析引擎"选项决定
    │
    ├─ Step 2: 规则脱敏（正则匹配）
    │   └─ 🟢 全程本地，零网络请求
    │
    ├─ Step 3: AI辅助脱敏（可选）
    │   ├─ 🟢 本地AI：数据不出机器
    │   └─ 🟡 云端AI：文本发送至云端
    │
    ├─ Step 4: AI验证（可选）
    │   ├─ 检查是否有遗漏的敏感信息
    │   └─ 安全级别同Step 3
    │
    └─ Step 5: 代号回填
        └─ 根据代号策略生成映射表
```

### 5.2 脱敏规则

系统预置18类规则，涵盖：
- 个人信息：姓名、身份证号、手机号、地址等
- 金融信息：银行卡号、金额等
- 案件标识：案号、仲裁号等
- 其他：邮箱、网址、车牌号等

用户可：
- 启用/禁用单条规则
- 添加自定义规则（正则表达式）
- 使用AI生成规则

## 6. 各页面功能定位

### 6.1 材料库（原"知识库"）

**定位**：原始文件存储中心

- 存放所有原始文档（PDF/Word/图片等）
- 每份材料可标记为"原版"或"脱敏版"
- 支持文件夹关联（AI可直接读取本地文件夹）
- 提供全文检索和AI摘要

### 6.2 知识卡片（原"Wiki"）

**定位**：AI整理的结构化知识

- 基于脱敏版材料自动生成
- 以卡片形式呈现法律知识点
- 支持智能检索和问答
- 供AI智能体作为知识源使用
- 不包含原始敏感信息

### 6.3 案件卷宗（原"案件档案"）

**定位**：按案件维度组织材料

- 一个案件包含多份材料
- 材料可关联原版和脱敏版
- 支持AI分析案件材料
- 案件内材料可设置AI使用偏好（默认使用脱敏版）

### 6.4 文档工坊（原"文档智能"）

**定位**：文档处理工场

- 文档解析：提取文本
- 文档脱敏：替换敏感信息
- 安全配置：明确每个环节的数据安全级别
- 代号管理：全局一致的代号映射

## 8. 用户故事

### US-1: 保密文件处理
> 作为律师，我需要处理一份保密仲裁申请书，确保数据不离开我的电脑。
> - 解析引擎选择"仅本地"
> - 脱敏模式选择"规则脱敏"
> - 安全概览显示"🟢 全程本地处理，数据零外传"

### US-2: 批量脱敏
> 作为律所助理，我需要批量处理一个案件文件夹中的所有材料。
> - 选择文件夹批量导入
> - 设置全局代号策略
> - 系统自动识别跨材料中的同一主体

### US-3: 高精度OCR
> 作为研究人员，我需要解析一份扫描质量较差的历史仲裁裁决书。
> - 解析引擎选择"云端OCR"
> - 安全概览提示"🟡 部分环节使用云端"
> - 确认后使用MinerU API解析

### US-4: AI辅助脱敏
> 作为仲裁员，我需要确保脱敏没有遗漏，但不想数据上传云端。
> - 脱敏模式选择"规则+本地AI"
> - AI验证选择"本地AI验证"
> - 本地模型检查脱敏结果是否有遗漏

### US-5: 材料版本选择
> 作为律师，我在AI聊天中需要引用案件材料，但不想暴露当事人信息。
> - AI默认使用脱敏版材料
> - 需要查看原文时手动切换原版
> - 系统提示安全风险
