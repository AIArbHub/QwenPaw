## 重要改造：知识库"安装即内置"——重构成内容哈希自动同步

**用户纠正**：目标是打包进安装包、用户安装后自动内置。**"每次跑 sync 脚本"是开发态权宜之计，用户根本不会跑**。

**改造 `src/aiarb/knowledge.py`**：
把 `ensure_global_knowledge_base()` 从"只补缺失(copy-if-missing)"重构为**内容哈希追踪的安全自动同步**：

- 新增 `_file_hash()`（sha256）、`_load_sync_state()` / `_save_sync_state()`
- 状态文件 `~/.aiarb/knowledge_base/.kb_sync_state.json`（记录各内置文件写入时哈希，随用户数据走）
- 三态判断：
  1. 用户端不存在 → 复制（新装/新增内容自动送达）
  2. 包内已更新 + 用户端哈希==state记录（未改）→ **覆盖更新**（升级触达）
  3. 包内已更新 + 用户端哈希!=state（用户改过）→ **保留用户版**
  4. 仅用户端有的文件/目录（`_parsed`/`_desensitized`/`_wiki`/私有笔记）→ **完全不碰**
- 调用点不变：`_app.py:187`（启动）+ `init_cmd.py:265`（init）→ **无需用户操作**

**验证（隔离环境真实测试，非推测）**：
| 场景 | 结果 |
|---|---|
| 首次安装 | 自动内置 312 文件 |
| 缺失文件 | 自动补回 ✅ |
| 用户改过的内置文件 | 保留 ✅ |
| 用户私有数据 `_parsed` | 不碰 ✅ |
| 包升级改内容 | 自动送达 ✅ |
| 包新增文件 | 自动送达 ✅ |
（测试中一度"D失败"经甄别是**测试场景写错**（模拟的是用户修改），改用伪包目录 monkeypatch 后验证通过）

**真实环境**：已在 `~/.aiarb` 建立 state 基线（380→382 文件），`_parsed`/`_desensitized`/`_meta.json` 完好。

**文档同步修正**（否则误导）：
- `docs/knowledge-pipeline.md`：删除"必须跑 sync_kb_scaffold.py"的旧结论，改为说明运行时自动同步 + 三态表
- `scripts/sync_kb_scaffold.py` docstring：标注 **STATUS: development-only**，用户无需执行

**遗留同构问题（已澄清，非问题）**：最初判断"内置技能 overwrite=False 不会升级推送"——**核实后是误判**。
技能系统 `pool_service.py::_check_download_conflict` 原生就有 **`safe_update`** 机制：
- 用户未修改工作区技能副本 → `mode: "safe_update"`，允许下载更新（升级能推送）
- 用户改过副本 → 冲突，保留用户版
这与知识库哈希方案目标一致，**技能系统无需再改造**。
